* Installing GRIN Siphon

** Prerequisites

- Python 3.11 or higher
- [[https://pdm-project.org][PDM]] (Python Dependency Manager)
- A Google Cloud project with the Google Drive API enabled and OAuth2
  credentials (see [[*Google Credentials]] below)
- AWS credentials with access to your target S3 bucket (see [[*AWS Credentials]] below)
- Your GRIN decryption passphrase (provided by Google)

** Get the Code

#+begin_src shell
git clone https://github.com/pulibrary/grin_siphon.git
cd grin_siphon
#+end_src

** Install Dependencies

#+begin_src shell
pdm install -G dev
#+end_src

This installs all runtime and development dependencies into a managed
virtual environment.

** Configure the Pipeline

Copy the configuration template and edit it for your installation:

#+begin_src shell
cp config-template.yml config.yml
#+end_src

Edit =config.yml= and fill in your values. Key fields to change:

- =global.object_store= — your S3 bucket name
- =global.ledger_file= — path to your book ledger CSV
- =global.processing_bucket= / =global.finished_bucket= — local working directories
- =global.token_bag= — directory to hold tokens awaiting pipeline entry
- =filters.decryptor.decryption_passphrase= — your GRIN decryption passphrase
- All =buckets[*].path= values — filesystem paths for each pipeline stage

By default all paths are under =/var/tmp/grin/=, which works for local
development and testing. Change them for production deployments.

You can also set the =PIPELINE_CONFIG= environment variable to point to
your config file if it is not named =config.yml= or is not in the
current directory:

#+begin_src shell
export PIPELINE_CONFIG=/path/to/config.yml
#+end_src

** Create the Pipeline Directories

The bucket directories must exist before the pipeline can run. The
following command creates them all at once, using the default paths
from =config-template.yml=:

#+begin_src shell
mkdir -p /var/tmp/grin/{pipeline/{start,requested,converted,downloaded,decrypted,stored,done},processing,finished,token_bag}
#+end_src

If you changed the paths in =config.yml=, adjust the command accordingly.

** Google Credentials

GRIN Siphon uses the Google Books API to download converted book files.
You will need two files: a /client secrets/ file (downloaded from
Google Cloud Console) and a /token/ file (generated by an OAuth2 flow).

*** Step 1: Create OAuth2 credentials in Google Cloud Console

1. Go to [[https://console.cloud.google.com][console.cloud.google.com]] and select your project.
2. Navigate to *APIs & Services → Library* and enable the *Google
   Drive API* if it is not already enabled.
3. Navigate to *APIs & Services → Credentials*.
4. Click *Create Credentials → OAuth 2.0 Client ID*.
5. Choose *Desktop app* as the application type.
6. Download the resulting JSON file. This is your =client_secret.json=.

Restrict its permissions so only you can read it:

#+begin_src shell
chmod 600 /path/to/client_secret.json
#+end_src

*** Step 2: Set environment variables

The credential helper script reads two environment variables. Add them
to your =.env= file in the project root (the Python =dotenv= library
will load them automatically):

#+begin_example
GOOGLE_SECRETS_FILE=/path/to/client_secret.json
GOOGLE_TOKEN_FILE=/path/to/token.json
#+end_example

Note: the zsh =dotenv= plugin will also detect a =.env= file when you
=cd= into the project. If it prompts you to source the file, answer
/never/ — the =.env= file is intended to be read by Python, not
sourced by the shell.

*** Step 3: Run the credential helper

The credential helper runs an OAuth2 loopback server on port 53682. It
does *not* open a browser on the server — it prints a URL for you to
open on your local machine. Google redirects back to =localhost:53682=
after authorization, so that port must be reachable from your local
browser.

*If you are running on a headless remote server*, forward the port
before running the script. In a separate local terminal:

#+begin_src shell
ssh -L 53682:localhost:53682 user@your-server
#+end_src

Then, back on the server, run:

#+begin_src shell
python src/clients/create_creds.py
#+end_src

The script prints a URL. Open it in your local browser, authorize the
application, and Google will redirect to =localhost:53682=. The tunnel
carries that callback to the server, which writes the token to the path
specified in =GOOGLE_TOKEN_FILE=.

*If you are running locally* (not over SSH), no tunnel is needed — just
run the script and open the URL that is printed.

The token is refreshed automatically by the pipeline when it expires.
You only need to run this script once per machine (or after revoking
access).

** AWS Credentials

GRIN Siphon uses boto3 to upload processed files to S3. boto3 follows
the standard AWS credential chain, so the simplest setup is to
provide credentials in =~/.aws/credentials=:

#+begin_src conf
[default]
aws_access_key_id = YOUR_ACCESS_KEY_ID
aws_secret_access_key = YOUR_SECRET_ACCESS_KEY
#+end_src

And a region in =~/.aws/config=:

#+begin_src conf
[default]
region = us-east-1
#+end_src

Restrict permissions on the credentials file:

#+begin_src shell
chmod 600 ~/.aws/credentials
#+end_src

If you are migrating from another machine, you can copy these files
directly — they are plain text.

The IAM user or role associated with these credentials must have S3
access to the bucket named in =global.object_store= in your
=config.yml=.

** Verify the Installation

Run the test suite to confirm everything is wired up correctly:

#+begin_src shell
pdm test
#+end_src

All tests should pass. If the reporter test fails with a credentials
error, double-check your AWS credentials and bucket name.
